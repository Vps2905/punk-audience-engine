# Module 2 embedding benchmark dataset runbook

## Purpose

This workflow creates the immutable, reviewed evaluation dataset used to
compare and approve embedding models. It does not select a model, build
production features, activate an audience, or export data.

Relevance labels must come from reviewed business constraints. They must not be
generated by the candidate model being evaluated. The benchmark may contain
only privacy-safe aggregate feature text or curated synthetic evaluation
documents. It must never contain raw MAIDs, device IDs, coordinates, movement
paths, emails, phone numbers, or reachable audience counts.

## 1. Export the existing privacy-safe feature catalog

Use the least-privilege feature-reader database URL. The export reads the
feature identity, normalized location, category, daypart, safe trait text,
privacy status, and rights status. It does not read or export embeddings,
cohort sizes, arbitrary metadata, or identifiers.

```bash
PYTHONPATH=. python scripts/export_safe_embedding_benchmark_catalog.py \
  --tenant-id "punk_internal" \
  --feature-set-id "feature_set_22221fdca49c5b66be462853" \
  --feature-set-version 1 \
  --catalog-id "punk-historical-safe-features" \
  --catalog-version "2026-07-08" \
  --output "/tmp/punk-historical-safe-feature-catalog.json" \
  --confirm-offline-evaluation-only
```

The current historical feature set contains 86 documents. Production policy
requires at least 100 distinct documents, so this export cannot pass the
benchmark coverage gate by itself. Do not duplicate or relabel documents to
inflate coverage. Add separately reviewed, privacy-safe aggregate or curated
synthetic catalogs representing missing languages, geographies, categories,
dayparts, exclusions, and adversarial cases.

## 2. Author and review gold cases

First generate the content-addressed curation plan:

```bash
PYTHONPATH=. python \
  scripts/plan_production_embedding_benchmark_curation.py \
  --document-catalog \
    "/tmp/punk-historical-safe-feature-catalog.json" \
  --output "/tmp/punk-embedding-curation-plan.json" \
  --confirm-no-auto-approval
```

The plan reports exact document and taxonomy deficits, distribution evidence,
and hard-negative pairs that differ in exactly one structured constraint. It
does not generate documents or queries and cannot approve labels. This keeps
the benchmark independent from the model it will evaluate.

Start from
`samples/embedding_benchmark_case_catalog.example.json`. Every supported case
must name its relevant documents and explicit location, category, and daypart
constraints where applicable. Every hard negative must violate at least one
explicit constraint. Every unsupported-location case must name a location that
is absent from all supplied document catalogs.

Multilingual paraphrases may share a `semantic_group_id`, but their relevant
documents, hard negatives, constraints, and unsupported status must be
identical. A named reviewer and UTC review timestamp are required.

The checked-in examples demonstrate schema only. They are intentionally too
small to pass production coverage.

## 3. Compile the immutable dataset

Provide one or more independently fingerprinted document catalogs:

```bash
PYTHONPATH=. python \
  scripts/build_production_embedding_benchmark_dataset.py \
  --benchmark-id "punk-global-retrieval-eval" \
  --dataset-version "<immutable-version>" \
  --document-catalog \
    "/tmp/punk-historical-safe-feature-catalog.json" \
  --document-catalog \
    "<reviewed-safe-supplemental-catalog.json>" \
  --case-catalog "<reviewed-gold-case-catalog.json>" \
  --output "/tmp/punk-production-embedding-dataset.json" \
  --readiness-report \
    "/tmp/punk-production-embedding-dataset-readiness.json" \
  --confirm-gold-label-review-complete
```

The builder fails closed for:

- duplicate document IDs across catalogs;
- relevant documents that contradict explicit constraints;
- hard negatives that satisfy every explicit constraint;
- unsupported locations present in the document catalog;
- inconsistent multilingual gold labels;
- unsafe catalog source types, privacy status, rights, or raw identifiers;
- missing named review evidence.

The dataset and readiness report are written atomically. The dataset embeds
the exact case-catalog fingerprint, all document-catalog fingerprints, the
reviewer, review time, schema version, and builder version.

## 4. Interpret readiness

`ready_for_model_evaluation: true` means only that the reviewed dataset meets
the minimum versioned coverage policy. It does not mean a model passed.

`blocked_insufficient_benchmark_coverage` is an expected safe result until all
required case, document, language, geographic, category, daypart,
hard-negative, unsupported-location, and multilingual coverage is present.

After readiness passes, run the model benchmark documented in
`module2_production_feature_build_runbook.md`. Model registration still
requires a passing report for the exact immutable dataset and exact immutable
model revision.

## Current data limitation

The real provider snapshot ends on 8 July 2026 and remains
`historical_preview`. It may support offline retrieval evaluation but cannot
